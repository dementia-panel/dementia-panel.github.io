# Справочник API

Подключите биллинг, Telegram-бота или другой внешний сервис к dementia. Справочник содержит **43 метода**, доступных по сервисному API-ключу.

## Авторизация

Создайте именованный API-ключ в админке и сохраните его при выдаче. Передавайте ключ в каждом запросе:

```http
Authorization: Bearer dementia_api_YOUR_KEY
```

Ключи бессрочные. Удаление немедленно отзывает доступ к API. Вход администратора, настройки интеграций и протокол агента ноды используют отдельную авторизацию и не входят в этот справочник.

## Первый запрос

| Параметр | Значение |
| --- | --- |
| Метод | GET |
| URL | `https://panel.example.com/api/admin/users` |
| Authorization | `Bearer dementia_api_YOUR_KEY` |
| Query | `page=1&per_page=25` |

```sh
curl --fail-with-body 'https://panel.example.com/api/admin/users?page=1&per_page=25' \
  -H 'Authorization: Bearer dementia_api_YOUR_KEY'
```

## Формат запросов

Для JSON задайте `Content-Type: application/json`. Неизвестные поля отклоняются, стандартный лимит тела — 64 КиБ. UUID записываются строчными буквами с дефисами, даты — в RFC3339. Объёмы в байтах — int64: сохраняйте целочисленную точность.

В маршрутах пользователя можно указать UUID или положительный Telegram ID. Остальные идентификаторы пути — UUID. Создание через `POST` принимает **один объект**. Добавление устройства сохраняет существующие устройства и ключи.

## Ошибки

```json
{
  "error": "resource not found"
}
```

Возможные статусы перечислены у каждого метода. `204` означает отсутствие тела ответа. `202` — фоновая операция принята; проверяйте результат в ресурсе. Заголовок ответа `X-Request-ID` позволяет найти запрос в логах сервера.
