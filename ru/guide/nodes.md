# Ноды

Подключите VPS — backend установит ноду через SSH.

## Подготовьте сервер

- Ubuntu или Debian, root либо пользователь с правами sudo.
- Доступный `/dev/net/tun` на VPS.
- Исходящий HTTPS-доступ к GitHub и адресу панели `PUBLIC_URL`.
- Входящий UDP на выбранном VPN-порту, по умолчанию `1234` для новых нод.

## Добавьте ноду

Откройте **Ноды → Подключить ноду**. Укажите имя, IP-адрес VPS, SSH-порт, логин и пароль. Выбранное имя применяется при установке.

Установщик проверит ОС, установит Docker и развернёт AmneziaWG. Установка может занимать до 15 минут. Этапы и ошибки отображаются в карточке ноды.

## Управление нодой

| Действие | Результат |
| --- | --- |
| Переименовать | Меняет отображаемое название. |
| Приостановить | Отключает VPN-доступ после синхронизации ноды. |
| Проверить связь | Ожидает новый отчёт агента; это не ICMP ping. |
| Перезапустить | Передаёт агенту запрос перезапуска. |
| Удалить из панели | Удаляет записи и назначения без подключения по SSH. |
| Удалить и очистить VPS | Подключается через SSH, останавливает контейнеры и удаляет установленные файлы ноды. |

## Повторная установка

Прочитайте ошибку в карточке ноды. Если VPS переустановлен и SSH-ключ изменился, явно разрешите новый ключ при повторной установке. По умолчанию известный ключ не заменяется автоматически.

Журнал установщика описан в разделе [Решение проблем](./troubleshooting).

## Подключённые пользователи

В карточке ноды отображается **Подключено пользователей**. API возвращает это значение в поле `online_user_count` ответов с данными ноды.

Пользователь учитывается один раз на каждой ноде, даже если подключены несколько его устройств или записей доступа. Оценка основана на отчёте ноды моложе одной минуты и VPN-рукопожатии моложе трёх минут. Отключённые пользователи, просроченный или отключённый доступ, исчерпанный лимит трафика и приостановленные или несинхронизированные ноды не учитываются. Если отчёты перестали приходить, счётчик обнуляется после истечения окна актуальности.

## Мобильная сеть и определение страны

Новые профили используют MTU 1280, чтобы уменьшить фрагментацию пакетов в мобильных сетях. Для применения нового MTU импортируйте профиль заново. Для новых нод по умолчанию выбран UDP-порт 1234; установленные ноды сохраняют прежний порт. Проверьте входящий UDP-порт в брандмауэре VPS и у хостинг-провайдера.

Если нода недоступна только через мобильный интернет, сравните работу того же профиля по Wi-Fi и проверьте доступность IP VPS у оператора. В [инструкции Amnezia](https://docs.amnezia.org/troubleshooting/self-hosted-amneziawg-not-working/) описана блокировка IP или сигнатуры протокола оператором. Изменение MTU или порта не устранит блокировку самого IP; для этого нужен другой IP или хостинг-провайдер.

Если сервис показывает Россию при подключённом VPN, отключите раздельное туннелирование и сравните публичный IP соединения с IP ноды. Сервис также может использовать устаревшую базу геолокации IP. См. [инструкцию Amnezia по выбору локации](https://docs.amnezia.org/documentation/instructions/choose-location/). Сейчас проект маршрутизирует IPv4-трафик; поддержка IPv6-туннеля не заявлена.
